# Architecture

`bdetect` is a single-process C++20 batch pipeline with five boundaries: bounded JSON parsing, event extraction, normalization, feature/rule evaluation, and JSONL evidence output. OpenSSL EVP provides rule and dataset SHA-256 digests. There is no kernel collector, online queue, blocking action, or process-attribution path.

The replay path hashes the rule bytes, hashes the input file before and after parsing, validates event fields, removes exact duplicate IDs, and marks conflicting IDs or late events as unknown evidence. Optional producer session/sequence metadata is scoped by host, source, and session; sequence gaps and collisions, or mixed sequence availability for one host/source, conservatively add unknown coverage. Accepted events are ordered by host/time/ID. Optional pacing maps a separate global event-time timeline to monotonic deadlines; the fast default skips waits. Both modes use the same event-time windows and scoring.

At each distinct event-second endpoint, `evaluate` maintains an overlapping `[end - window_seconds, end]` interval. It counts unique modified, renamed, deleted, and extension features. Versioned rule objects declare feature, comparison operator, threshold, weight, and minimum samples. Each match adds a configured contribution and structured evidence to the decision. A degraded source or insufficient required sample count results in `unknown` rather than benign. As the left edge advances, it releases the string payload of events that can no longer enter a window; event objects and timestamps remain until the batch finishes. Optional `--stats-out` emits a separate replay-stats.v1 sidecar with per-decision percentiles and does not change decision records.

The fixture generator writes harmless event metadata for eight differentiated benign labels and four synthetic suspicious patterns under a caller-provided sandbox. The labels are generated beside the data and are not an independent holdout. Metric output is a pipeline wiring check, not detection-quality evidence.

`evaluate_labels` always writes the existing JSON confusion metrics. Optional `--csv-report` adds the same metrics as rows with explicit numerators, denominators, and values, followed by decision rows sorted by window end, entity key, and start time. Optional `--html-report` emits a static escaped HTML rendering of those metrics and rows. Both optional timelines retain at most 100,000 records; prediction parsing is capped at 1,000,000 records. Neither report includes raw file paths, and the HTML page labels the result as simulation-only. Report generation was added after the last technical verification; its behavior remains unverified.

`analyze-rules` reads decision reason IDs and counts each rule's active decisions and each pair's joint, exclusive, and absent activations. It reports Jaccard similarity and phi correlation in `bdetect.rule_analysis.v1`, with caps of 1,000,000 decision records, 256 distinct rules, and 10,000,000 pair updates. The analysis is descriptive: adjacent overlapping windows are dependent, and the program does not modify rules or weights. This feature was also added after the last technical verification.

Resource limits cap each input file at 512 MiB, JSON event lines at 1 MiB, decision lines at 64 MiB, total events and evaluated predictions at 1,000,000, rules at 256, host cardinality, labels, and optional report timeline rows. `analyze-rules` also caps pair-update work at 10,000,000. Parsed input and normalized copies coexist during loading/normalization; the parsed input vector is released before scoring. Window-scoped string payloads are released after the left boundary advances, but event objects and indexes remain until processing ends. A bounded online event queue, watermark finalization, interval-scoped unknown decisions, and a frozen dev/holdout process remain future work. Sequence analysis is finalized over the loaded batch; it does not yet implement an online lateness watermark. File paths remain present in decision evidence where needed for explainability, so report omission does not amount to repository-wide path pseudonymization.
