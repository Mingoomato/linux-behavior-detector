# Architecture

`bdetect` is a single-process C++20 batch pipeline with five boundaries: bounded JSON parsing, event extraction, normalization, feature/rule evaluation, and JSONL evidence output. OpenSSL EVP provides rule and dataset SHA-256 digests. There is no kernel collector, online queue, blocking action, or process-attribution path.

The replay path hashes the rule bytes, hashes the input file before and after parsing, validates event fields, removes exact duplicate IDs, and marks conflicting IDs or late events as unknown evidence. Optional producer session/sequence metadata is scoped by host, source, and session; sequence gaps and collisions, or mixed sequence availability for one host/source, conservatively add unknown coverage. Accepted events are ordered by host/time/ID. Optional pacing maps a separate global event-time timeline to monotonic deadlines; the fast default skips waits. Both modes use the same event-time windows and scoring.

At each distinct event-second endpoint, `evaluate` maintains an overlapping `[end - window_seconds, end]` interval. It counts unique modified, renamed, deleted, and extension features. Versioned rule objects declare feature, comparison operator, threshold, weight, and minimum samples. Each match adds a configured contribution and structured evidence to the decision. A degraded source or insufficient required sample count results in `unknown` rather than benign.

The fixture generator writes harmless event metadata for eight differentiated benign labels and four synthetic suspicious patterns under a caller-provided sandbox. The labels are generated beside the data and are not an independent holdout. Metric output is a pipeline wiring check, not detection-quality evidence.

Resource limits cap JSON lines, total events, fields, rule count, and host cardinality. The offline design keeps both parsed input and normalized copies alive, and output windows can approach event count. A bounded streaming watermark, interval-scoped unknown decisions, TTL eviction, path pseudonymization, and a frozen dev/holdout process remain future work. Sequence analysis is finalized over the loaded batch; it does not yet implement an online lateness watermark.
